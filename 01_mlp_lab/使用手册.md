# MLP 组件与决策边界实验室使用手册

> 本文用于查询参数、日志、绘图和命令细节，不需要从头顺序阅读。首次运行请先看 `快速上手与练习指南.md`，主要操作入口为 `00_一键体验.ipynb`。

## 1. 内容概览

这个实验室用二维数据展示 MLP 的训练过程和组件替换效果，包含：

- 月牙、同心圆、三分类螺旋三种离线数据；
- ReLU、Tanh、Sigmoid 激活函数；
- Cross-Entropy 与合法的 MSE 分类方案；
- SGD、Momentum、Adam 优化器；
- 隐藏层深度、隐藏层宽度与 Dropout；
- 训练阶段决策边界、误判点、loss、accuracy、gradient norm、参数量和耗时；
- 独立的数据与任务前置说明图；
- 每次训练的 JSON、TXT 和 CSV 历史日志；
- Jupyter Notebook 分步入口和 VS Code/终端一键入口。

6 份 notebook 通过 `mlp_lab` 包调用同一套实现，`demo.py` 通过兼容入口 `core.py` 调用相同代码，不会维护两套训练逻辑。

## 4. CPU 与 GPU 如何切换

CPU 和 GPU 使用同一套模型与训练代码，只改变张量和模型所在设备。

### 强制使用 CPU

```bash
python demo.py --device cpu --experiment baseline
```

Notebook：

```python
result = quick_demo(device="cpu")
```

### 指定课堂分配的 GPU

```bash
python demo.py --device cuda:x --experiment baseline
```

Notebook：

```python
result = quick_demo(device="cuda:x")
```

把 `x` 替换为课堂指定的 GPU 编号。例如分配第 3 块 GPU 时写成 `cuda:3`。
共享服务器上不要使用 `auto`，否则多个进程容易集中到默认 GPU。

如果当前 PyTorch 检测不到 CUDA，程序会立即给出中文错误，不会静默切换到 CPU。

> 小型 MLP 的计算量很少，GPU 不一定比 CPU 快。GPU 需要启动 CUDA 上下文并传输数据，固定开销可能大于训练本身。设备对比应关注代码兼容和趋势，不把这个小模型作为 GPU 性能基准。

## 5. 可以调整哪些参数

查看全部命令行参数：

```bash
python demo.py --help
```

### 5.1 通用参数

| 参数 | 可选值或示例 | 作用 |
|---|---|---|
| `--device` | `cpu`、`cuda:x`、`auto`、`cuda` | 选择运行设备；课堂默认 CPU，`x` 替换为分配编号 |
| `--mode` | `fast`、`extended` | fast 使用较少样本和 epoch；extended 用于更长实验 |
| `--dataset` | `moons`、`circles`、`spiral` | 切换二维分类数据 |
| `--experiment` | 见下一节 | 选择基线或单变量对比 |
| `--seed` | `42`、`7` 等整数 | 控制数据、初始化与 shuffle |
| `--epochs` | `20`、`80`、`200` | 覆盖 mode 的默认训练轮数 |
| `--noise` | `0.1`、`0.45`、`0.7` | 调整数据重叠程度 |
| `--save-dir` | `outputs` | 把图保存到指定目录 |
| `--log-dir` | `logs` | 修改自动实验日志的保存目录 |
| `--no-log` | 无参数值 | 本次训练不保存日志 |
| `--no-show` | 无参数值 | 不弹出图形窗口，适合批量运行 |

fast 模式默认 600 个样本、80 个 epoch；extended 模式默认 1200 个样本、200 个 epoch。

### 5.2 模型与训练参数

| 参数 | 可选值或示例 | 作用 |
|---|---|---|
| `--hidden-sizes` | `8,8`、`32,32`、`64,64,64` | 设置每个隐藏层的宽度；数字个数就是隐藏层数 |
| `--activation` | `relu`、`tanh`、`sigmoid` | 设置所有隐藏层的激活函数 |
| `--loss` | `cross_entropy`、`mse` | 设置分类损失 |
| `--optimizer` | `sgd`、`momentum`、`adam` | 设置参数更新方法 |
| `--learning-rate` | `0.001`、`0.02`、`0.1` | 设置更新步长 |
| `--dropout` | `0.0`、`0.2`、`0.5` | 设置隐藏层激活后的随机失活比例 |

示例：

```bash
python demo.py --dataset circles --hidden-sizes 16,16 --activation tanh \
  --optimizer momentum --learning-rate 0.03 --dropout 0.2
```

Cross-Entropy 直接接收 raw logits。选择 MSE 时，`mlp_lab/engine.py` 会先把 logits 转为类别概率，再与 one-hot 目标比较；不会把类别编号直接当连续数回归。

## 6. 如何运行组件对比

组件对比会保持数据划分、随机种子、epoch 和其他组件不变，只替换目标组件。

```bash
python demo.py --experiment activation  # ReLU / Tanh / Sigmoid
python demo.py --experiment depth       # 1 / 2 / 3 个隐藏层
python demo.py --experiment width       # 8 / 32 / 64 的隐藏宽度
python demo.py --experiment loss        # Cross-Entropy / MSE
python demo.py --experiment optimizer   # SGD / Momentum / Adam
python demo.py --experiment dropout     # 0.0 / 0.2 / 0.5
```

一次运行全部对比：

```bash
python demo.py --experiment all
```

`all` 会连续训练多组模型，第一次使用建议先运行单个对比。

## 8. 实验日志如何保存和比较

`demo.py` 每次完成训练后自动保存日志，默认目录为 `01_mlp_lab/logs`：

- `时间_实验名.json`：配置、环境、源码 SHA-256、最终指标和完整逐轮曲线；
- `时间_实验名.txt`：与终端一致的结果摘要；
- `history.csv`：每个配置占一行，便于按日期、基线配置或准确率筛选比较。

日志会联合计算 `core.py` 与 `mlp_lab/*.py` 的源码 SHA-256。任一训练模块发生变化时，
哈希都会改变，因此能够区分“参数变化”和“实现变化”。

指定其他日志目录：

```bash
python demo.py --experiment baseline --log-dir outputs/experiment_logs
```

临时关闭日志：

```bash
python demo.py --experiment baseline --no-log
```

运行 `--experiment all` 时，六类组件对比分别保存一组日志，并共同追加到
`history.csv`。数据画廊和前置说明不训练模型，因此不写性能日志。

## 9. 如何阅读图形

### 决策边界

- 浅蓝、浅红、浅绿背景：模型在该坐标区域预测的类别；
- 实心圆：训练样本；
- 叉号：测试样本；
- 更大、更粗的叉号：被模型误判的测试样本。

观察重点不是边界越曲折越好，而是边界能否覆盖真实类别，同时不过度追随噪声点。

### Loss

- 持续下降：优化器正在减少当前损失；
- 大幅震荡或上升：学习率可能过高；
- 很早停止下降：可能是学习率过低、梯度过小或模型容量不足。

不同损失函数的数值尺度不同，不能只比较 loss 数字大小；应比较各自下降趋势和最终分类表现。

### Accuracy

- 训练和测试曲线共同上升：模型在学习且能够泛化；
- 训练继续上升、测试下降：出现过拟合迹象；
- 两条曲线都较低：可能欠拟合或尚未收敛。

### Gradient norm

- 使用对数纵轴；
- 长期接近零：可能存在梯度消失或饱和；
- 出现极大尖峰：可能是学习率过高或更新不稳定；
- 梯度较小不自动等于错误，要结合 loss 与 accuracy 判断。

## 10. 推荐的使用顺序

1. `data_and_task.py`：理解数据、输入输出、任务和默认基线；
2. `baseline`：理解决策边界如何随训练形成；
3. `activation`：把激活函数与梯度联系起来；
4. `optimizer`：观察更新规则对收敛速度的影响；
5. `loss`：理解分类输出和目标表示；
6. `depth`、`width`、`dropout`：讨论容量、欠拟合、过拟合和正则化；
7. 修改 2–5 行配置，在参数预算内完成挑战；
8. 打开 `logs/history.csv`，与之前的基线记录进行比较。

## 11. 保持对照公平

恢复基线后一次只修改一个参数，并保持相同 `--seed`。如果目标是寻找最佳组合，应先完成单变量实验，再明确说明已经从“解释组件”切换到“超参数搜索”。

## 12. Linux 图片中的中文显示为方框

出现 `Glyph ... missing from font(s) DejaVu Sans`，说明 Matplotlib 没有找到中文字体，
并不是训练代码或 Notebook 文件编码错误。

当前项目已在 `assets/fonts` 中附带 Noto Sans CJK SC，并由统一绘图入口自动加载。
更新项目后执行：

```bash
git pull
conda activate dl2026
python test_mlp_smoke.py
```

随后在 VS Code 中执行 `Restart Kernel` 和 `Run All`。Notebook 已经保存的旧图片不会
因为字体文件出现而自动改变，必须重新运行对应单元格。

若仍有问题，先检查字体文件是否存在：

```bash
ls -lh assets/fonts/NotoSansCJKsc-Regular.otf
```

不需要使用管理员权限安装字体，也不需要修改服务器全局字体目录。
