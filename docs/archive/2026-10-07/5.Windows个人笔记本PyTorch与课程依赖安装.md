# Windows 个人笔记本：PyTorch 与课程依赖安装指南

> 适用项目：`2026DeeplearningDemo`
>
> 命令核对日期：2026-09-10。本文固定课程版本，追求课堂一致性，不追求每天更新到最新版。
>
> 安全原则：先检测，再手动选择安装路线。检测脚本不联网、不安装软件、不修改驱动，也不修改 PowerShell 全局策略。

## 1. 先看结论

本课程在 Windows 上只有两条正式路线：

| 电脑情况 | 课程路线 | 能否完成四个实验 |
|---|---|---:|
| 没有 NVIDIA 显卡，只有 Intel / AMD 显卡，或不确定配置 | CPU 版 PyTorch | 可以 |
| NVIDIA 显卡且 `nvidia-smi` 正常 | NVIDIA CUDA 版 PyTorch | 可以，也可在同一环境运行 CPU |
| 能看到 NVIDIA 显卡，但 `nvidia-smi` 不可用 | 先用 CPU；课后再处理官方驱动 | 可以 |
| 已安装 PyTorch，且 `torch.cuda.is_available()` 为 `True` | 不重装 | 可以 |

四个实验都能在 CPU 上运行。GPU 是速度教学的可选项，不是完成课程的前提。当前小模型的计算量很小，GPU 也可能比 CPU 慢；这是有效实验现象，不是安装失败。

课程统一使用：

```text
64 位 Windows
Miniconda
Conda 环境名：dl2026
Python 3.11
PyTorch 2.11.0
```

选择 Python 3.11 是为了与课程 Linux 环境和现有依赖保持一致。不要把包装进 `base`，也不要把系统 Python、Conda Python 和 Microsoft Store Python 混在一起。

### Windows 版本提醒

本课程不要求重装或升级操作系统。Anaconda 已从 2026-06-30 起停止验证 Windows 10 上的新包；既有环境和已经构建的包仍可能工作。Windows 10 电脑先在原系统中运行预检并尝试 CPU 路线，若安装不顺利就使用现有 Linux 课程服务器，不为本课程更换系统。Windows 11 同样先预检，不做无关的系统改动。

## 2. 第 0 步：先运行只读预检

先取得课程项目。已有项目文件夹可直接继续；没有 Git 时，可以先在浏览器中下载项目 ZIP 并解压。

在资源管理器中打开项目根目录，在地址栏输入 `powershell` 后按 Enter，然后运行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\check_windows_environment.ps1"
```

这里的 `Bypass` 只对这一次新开的 PowerShell 进程生效，不会修改系统或用户的全局执行策略。脚本只读取以下信息：

- Windows 版本、系统位数、CPU 和内存；
- Intel、AMD 或 NVIDIA 显卡名称；
- Conda 是否安装、当前环境是否激活；
- 当前 Python、pip 和 PyTorch；
- NVIDIA 驱动、显存以及驱动支持的 CUDA 上限；
- Git 和 VS Code 命令是否可见。

看到 `[MISSING]` 或 `[NOT READY]` 不代表脚本出错，它们就是待处理的检测结果。最后一段 `Manual next step` 会给出应走的路线，但不会替你安装。

需要把结果发给教师排查时，可以保存一份文本：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\check_windows_environment.ps1" | Tee-Object -FilePath "$env:TEMP\dl2026_windows_preflight.txt"
```

诊断文本会保存在 Windows 临时目录中，可能含有本机用户名和安装路径；发给教师前先检查，不要公开上传。

## 3. 不要混淆四个 CUDA 概念

| 名称 | 在哪里 | 本课程如何处理 |
|---|---|---|
| NVIDIA 显卡 | 电脑硬件 | 没有也可以用 CPU |
| NVIDIA 驱动 | Windows 系统 | `nvidia-smi` 正常是 GPU 路线的前提 |
| `nvidia-smi` 的 `CUDA Version` / `CUDA UMD Version` | 驱动能力上限 | 不是“本机已安装 Toolkit”的版本 |
| `torch.version.cuda` | 当前 PyTorch wheel 自带的 CUDA runtime | 安装后用它确认选中了哪种 PyTorch build |
| CUDA Toolkit / `nvcc` | CUDA 开发工具链 | 课堂 Demo 不需要单独安装 |

本课程使用 PyTorch 官方预编译 wheel。只运行这些实验时，不要先安装整套 CUDA Toolkit，不要从网上复制 CUDA DLL，也不要为了让数字完全相同而反复改驱动。只有以后需要从源码编译 PyTorch 或编译自定义 CUDA 扩展时，本地 Toolkit 才成为单独问题。

## 4. 前置条件：完成 Miniconda 和课程环境配置

Miniconda 的下载安装、安装路径、环境变量、PowerShell 初始化和 `dl2026` 环境创建，统一以 [1.3：Windows 笔记本安装与配置 Miniconda](./1.3%28补充材料%29Windows笔记本安装与配置Miniconda.md) 为准，本教程不再重复。

完成 `1.3` 后，在新打开的 PowerShell 中执行下面四条检查命令：

```powershell
conda activate dl2026
python --version
where.exe python
python -m pip --version
```

只有在 Python 显示为 3.11，且 `where.exe python` 的第一条路径位于 `...\envs\dl2026\python.exe` 时，才继续安装 PyTorch。任一检查不符合预期，都回到 `1.3` 对应章节排查，不要在错误环境中安装软件包。

## 5. 进入项目并安装通用依赖

如果使用 Git，可在准备存放代码的目录中执行：

```powershell
git clone https://github.com/AYHQChang/2026DeeplearningDemo.git
cd ".\2026DeeplearningDemo"
```

已经下载 ZIP 或已有项目时，直接进入项目根目录。确认当前目录里能看到 `requirements.txt` 后运行：

```powershell
python -m pip install --only-binary=:all: -r requirements.txt
```

项目只需要 `torch`，不依赖 `torchvision` 或 `torchaudio`。PyTorch 单独安装，是为了让不同电脑选择不同的 CPU / CUDA wheel，同时避免通用依赖命令覆盖已经可用的 PyTorch。

## 6. 手动选择并安装 PyTorch

下面是本课程在 2026-09-10 核对并固定的 PyTorch 2.11.0 示例。只运行与自己电脑相符的一条，不要三条都运行。

### 路线 A：CPU，适合所有电脑

适用于没有 NVIDIA 显卡、只有 Intel / AMD 显卡、不确定配置，或只想先保证课堂可用的电脑：

```powershell
python -m pip install torch==2.11.0 --index-url https://download.pytorch.org/whl/cpu
```

### 路线 B：NVIDIA，驱动 CUDA 上限至少为 12.8

适用于预检中 `nvidia-smi` 正常，且显示 `CUDA Version` / `CUDA UMD Version` 为 12.8、12.9、13.x 或更高的电脑。RTX 50 系列优先使用此路线：

```powershell
python -m pip install torch==2.11.0 --index-url https://download.pytorch.org/whl/cu128
```

### 路线 C：NVIDIA，驱动 CUDA 上限为 12.6 或 12.7

```powershell
python -m pip install torch==2.11.0 --index-url https://download.pytorch.org/whl/cu126
```

上述数字用于筛选候选 wheel，不是对所有 NVIDIA 型号的兼容承诺；较老显卡即使驱动数字满足，也必须以安装后的 `torch.cuda.is_available()` 和实际运行结果为准。验证失败时直接回到 CPU 路线。

### 如果 NVIDIA 驱动上限低于 12.6

课堂上先安装 CPU 版，或先使用 Linux 服务器。确实需要本机 GPU 时，再从笔记本厂商或 NVIDIA 官方渠道更新驱动，然后重新运行预检并查看 [PyTorch 官方安装选择器](https://pytorch.org/get-started/locally/)。不要用安装 CUDA Toolkit 的方式代替驱动更新。

### 已经安装过 PyTorch 时

- `torch.cuda.is_available()` 为 `True`：不重装，同一环境可分别运行 `cpu` 和 `cuda:0`。
- `torch.version.cuda` 为 `None`：当前是 CPU build。若想保留稳定的 CPU 环境，建议另建 `dl2026-gpu` 后再安装 CUDA 版。
- `torch.version.cuda` 有数值但 `torch.cuda.is_available()` 为 `False`：先检查当前 Conda 环境和 NVIDIA 驱动，不要继续叠加安装 Toolkit 或复制 DLL。

课程命令是可复现快照，不是永久最新版。若将来官方页面不再提供这些 wheel，以 [PyTorch Previous Versions](https://pytorch.org/get-started/previous-versions/) 和当前安装选择器为准，并先在课前验证，不在上课过程中临时升级全班环境。

## 7. 安装后验证

先查看 PyTorch 自己报告的结果：


合理输出有两类：

```text
CUDA available: False

PyTorch: 2.11.0+cu128
Build CUDA: 12.8
CUDA available: True
```

然后运行项目验收：

```powershell
python check_environment.py
```

全部通过后，重新运行预检脚本，最后应显示当前 Python、PyTorch build 和人工下一步建议：

```powershell

```

## 9. CPU / GPU 课堂命令

CPU 电脑可以直接运行 Transformer 的两 Epoch 预览：

```powershell
python device_speed_demo.py --lab transformer --devices cpu --preview-epochs 2
```

NVIDIA CUDA 环境可以在同一个 Python 环境中顺序比较 CPU 和 GPU：

```powershell
python device_speed_demo.py --lab mlp --devices cpu,cuda:0
python device_speed_demo.py --lab cnn --devices cpu,cuda:0
python device_speed_demo.py --lab rnn --devices cpu,cuda:0
python device_speed_demo.py --lab transformer --devices cpu,cuda:0 --preview-epochs 2
```

笔记本通常只有一块 NVIDIA GPU，因此编号通常是 `cuda:0`。脚本会输出实跑时间、每 Epoch 时间、预计完整时间、预计剩余时间、GPU 峰值显存和 CPU/GPU 加速比。不要根据一两个预览 Epoch 的 Accuracy 判断模型效果。

## 10. 常见问题

### Conda 或 Python 路径不正确

`conda` 无法识别、`python` 打开 Microsoft Store、`where.exe python` 指向错误环境等问题，统一按 `1.3` 第 11 节处理。本教程只处理 PyTorch 和课程依赖，不再维护第二套 Conda 排错步骤。

### 运行预检脚本时提示禁止执行脚本

使用本文给出的进程级入口：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\check_windows_environment.ps1"
```

不要执行来源不明的脚本，也不要把全局策略改成 `Unrestricted`。

### `No matching distribution found`

先检查是否为 64 位系统、Python 是否为 3.11、当前解释器是否来自 `dl2026`。不要在报错后连续尝试多个不明镜像或随机版本。

### 有 NVIDIA 显卡，但 `torch.cuda.is_available()` 是 `False`

按下面顺序判断：

1. `nvidia-smi` 是否能正常列出显卡；
2. `torch.version.cuda` 是否为 `None`；
3. `where.exe python` 是否指向 `dl2026`；
4. 再重新运行 `check_windows_environment.ps1`，保留完整输出。

`torch.version.cuda is None` 表示装了 CPU build；有 CUDA 数值但仍为 `False`，通常应先排查驱动和环境，而不是安装本地 Toolkit。

### AMD 或 Intel 显卡为什么不用 GPU

当前四个实验的统一入口只接受 `cpu` 和 `cuda:x`。PyTorch 2.11 的 ROCm wheel 是 Linux-only；Windows DirectML 和 Intel XPU 使用的也不是 `cuda:x`，还会引入另一套代码与测试边界。因此本课程 Windows 标准路线统一回退 CPU，不把试验性后端放进必做环境。

### GPU 为什么反而更慢

MLP、8×8 CNN、短序列 RNN 和小型 Transformer 都很小。GPU 初始化、数据搬运和 Kernel 启动开销可能超过并行计算收益。先看脚本报告的设备、训练时间和 Epoch 数，再解释结果，不把“GPU 必须更快”写成预设答案。

### 网络慢或课堂上下载失败

环境安装必须在课前完成。不要关闭 SSL 验证，也不要在课堂中临时更换来源不明的镜像。预检或冒烟测试未通过时，课堂上优先使用已经准备好的 Linux 服务器。
