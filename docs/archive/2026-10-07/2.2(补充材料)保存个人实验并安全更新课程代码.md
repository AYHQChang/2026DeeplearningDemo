# 保存个人实验并安全更新课程代码

## 这份教程解决什么问题

上课时，教师会继续更新课程项目。学生也会修改 Notebook、调整模型并保存实验结果。

如果教师和学生同时修改同一个文件，执行 `git pull` 时就可能发生冲突。因此，本课程统一采用下面的办法：

> **课程原始 Notebook 不修改；先复制一份个人 Notebook，只在个人副本中做实验。**

这样可以同时做到：

- 保留自己的代码、图表和运行结果；
- 下一次课正常获取教师更新；
- 不需要学习复杂的 Git 分支、合并和变基；
- 个人实验文件和课程原始文件放在同一目录，原有导入路径通常不需要修改。

本教程中的命令在 Linux 服务器终端中执行。命令区分大小写，路径中包含中文时请保留双引号。

---

## 一、先认识三类文件

### 1. 课程原始文件

例如：

```text
01_mlp_lab/05_自主修改练习.ipynb
```

它由教师维护，并由 Git 跟踪。以后执行 `git pull` 时，这类文件可能被更新。

### 2. 个人实验文件

例如：

```text
01_mlp_lab/我的作业_20260001_张三_MLP.ipynb
```

它由学生自己维护。项目已经通过 `.gitignore` 忽略所有以 `我的作业_` 开头的 Notebook，因此 `git pull` 不会把它当成课程文件处理。

统一命名格式：

```text
我的作业_学号_姓名_项目名.ipynb
```

例如：

```text
我的作业_20260001_张三_MLP.ipynb
我的作业_20260001_张三_CNN.ipynb
```

### 3. Git 忽略的含义

“忽略”不是“删除”，也不是“自动备份”。它只表示 Git 不管理这些个人文件。

因此：

- 正常执行 `git pull`，个人文件会保留；
- 个人文件不会自动上传到课程公共仓库；
- 学生仍然需要按要求提交或备份个人文件；
- 如果手动删除整个项目，个人文件也会一起被删除。

## 二、第一次课：建立自己的实验副本

下面以 MLP 项目为例。

### 第 1 步：进入课程项目

```bash
cd "$HOME/courses/Deeplearning2026"
```

解释：

- `cd` 表示进入一个目录；
- `$HOME` 表示当前学生自己的主目录；
- 双引号可以保护完整路径，建议保留。

确认当前位置：

```bash
pwd
```

预期输出类似：

```text
/home/你的用户名/courses/Deeplearning2026
```

### 第 2 步：确认 Git 状态

```bash
git status --short --branch
```

状态干净时，通常会看到：

```text
## main...origin/main
```

其中：

- `main` 是当前课程代码所在的分支；
- 没有出现其他文件名，表示课程原始文件没有被修改。

### 第 3 步：获取教师的最新版本

```bash
git pull --ff-only origin main
```

解释：

- `git pull` 下载教师发布的新版本；
- `origin` 是远程课程仓库的默认名称；
- `main` 是课程主分支；
- `--ff-only` 遇到复杂冲突时会停止，而不是自动生成学生不容易理解的合并结果。

如果看到下面的信息，表示当前已经是最新版：

```text
Already up-to-date.
```

不同 Git 版本也可能显示：

```text
Already up to date.
```

### 第 4 步：记录本次课程代码版本

```bash
git rev-parse --short HEAD
```

输出类似：

```text
a1b2c3d
```

这串字符是本次课程代码的版本号。建议把它写进实验记录，便于以后解释“这个结果是在哪一版代码上得到的”。

### 第 5 步：复制个人 Notebook

把下面命令中的学号和姓名改成自己的信息：

```bash
cp -i \
  "01_mlp_lab/05_自主修改练习.ipynb" \
  "01_mlp_lab/我的作业_20260001_张三_MLP.ipynb"
```

解释：

- `cp` 表示复制文件；
- 第一条路径是课程原始 Notebook；
- 第二条路径是新建的个人 Notebook；
- `-i` 表示如果目标文件已经存在，必须先询问，避免误覆盖之前的实验；
- 行末的 `\` 表示命令还没有结束，下一行仍属于同一条命令。

如果系统询问是否覆盖已有文件，例如：

```text
overwrite '...我的作业_20260001_张三_MLP.ipynb'?
```

输入 `n` 并按回车。不要覆盖旧作业，可以换一个文件名，例如增加日期或版本号。

### 第 6 步：确认个人文件已经生成

```bash
ls -lh "01_mlp_lab/我的作业_20260001_张三_MLP.ipynb"
```

只要能看到文件名、大小和时间，就说明复制成功。

再次检查 Git 状态：

```bash
git status --short --branch
```

个人 Notebook 不会出现在状态列表中，这是正常现象，因为它已被 `.gitignore` 忽略。

### 第 7 步：只打开个人副本

在 VS Code 左侧文件列表中，进入 `01_mlp_lab`，打开：

```text
我的作业_20260001_张三_MLP.ipynb
```

以后修改模型、增加单元格、运行实验和填写结论，都在这个文件中完成。

不要修改：

```text
05_自主修改练习.ipynb
```

## 三、实验过程中如何保存

### 1. 经常保存 Notebook

在 VS Code 中按：

```text
Ctrl + S
```

Notebook 保存的不只是 Python 代码，还可以保存 Markdown 解释、表格、图像和已经运行出的输出。

### 2. 在 Notebook 中记录课程版本

可以新建一个代码单元格，运行下面的 Python 代码：

```python
import subprocess

course_version = subprocess.check_output(
    ["git", "rev-parse", "--short", "HEAD"],
    text=True,
).strip()

print(f"本次实验使用的课程代码版本：{course_version}")
```

逐行解释：

- `import subprocess`：导入 Python 调用系统命令的工具；
- `git rev-parse --short HEAD`：查询当前 Git 版本号；
- `.strip()`：删除输出末尾多余的换行符；
- `print(...)`：把版本号显示在 Notebook 中。

### 3. 每次实验至少记录这些内容

建议在 Notebook 最后增加 Markdown 单元格，写清楚：

```markdown
## 本次实验记录

- 姓名：张三
- 学号：20260001
- 课程代码版本：a1b2c3d
- 我修改了什么：隐藏层从 32 改为 64，激活函数从 ReLU 改为 Tanh
- 为什么这样修改：比较网络宽度和激活函数对结果的影响
- 最终结果：验证集准确率……，训练时间……
- 我的发现：……
```

不要只提交一个最高准确率。教师更关注修改理由、对照是否公平、结果图和自己的解释。

## 四、第二次课：保留旧实验并获取教师更新

### 第 1 步：先保存并关闭正在编辑的 Notebook

先按 `Ctrl + S`。如果 Notebook 仍在运行，也要等待重要单元格结束，避免只保存了一半输出。

### 第 2 步：进入课程项目

```bash
cd "$HOME/courses/Deeplearning2026"
```

### 第 3 步：检查状态

```bash
git status --short --branch
```

如果只看到：

```text
## main...origin/main
```

说明课程原始文件没有被修改，可以继续更新。

如果出现以 `M` 开头的课程文件，例如：

```text
 M 01_mlp_lab/05_自主修改练习.ipynb
```

说明误改了课程原始文件。不要继续执行 `git pull`，先看本教程第六部分。

### 第 4 步：拉取教师更新

```bash
git pull --ff-only origin main
```

Git 会更新课程原始文件，但不会删除 `我的作业_*.ipynb`。

### 第 5 步：确认旧实验仍然存在

```bash
ls -lh "01_mlp_lab/我的作业_20260001_张三_MLP.ipynb"
```

### 第 6 步：开始新一轮实验

如果教师更新了原始 Notebook，建议从最新版原始文件再复制一份，不要直接把旧个人文件当成新模板：

```bash
cp -i \
  "01_mlp_lab/05_自主修改练习.ipynb" \
  "01_mlp_lab/我的作业_20260001_张三_MLP_第2次.ipynb"
```

这样会同时保留：

- 第一次课的个人实验；
- 第二次课教师发布的新内容；
- 第二次课的新实验副本。

## 六、误改官方 Notebook 后如何抢救

原则是：**先复制抢救个人内容，再恢复官方文件，最后更新。顺序不能颠倒。**

下面仍以 MLP 为例。

### 第 1 步：确认哪个文件被修改

```bash
git status --short
```

如果看到：

```text
 M 01_mlp_lab/05_自主修改练习.ipynb
```

表示这个课程原始文件已被修改。

### 第 2 步：先复制出个人副本

```bash
cp -i \
  "01_mlp_lab/05_自主修改练习.ipynb" \
  "01_mlp_lab/我的作业_20260001_张三_MLP_抢救版.ipynb"
```

### 第 3 步：确认抢救副本存在

```bash
ls -lh "01_mlp_lab/我的作业_20260001_张三_MLP_抢救版.ipynb"
```

还可以比较两个文件的校验值：

```bash
sha256sum \
  "01_mlp_lab/05_自主修改练习.ipynb" \
  "01_mlp_lab/我的作业_20260001_张三_MLP_抢救版.ipynb"
```

如果两行最前面的长字符串相同，说明复制内容一致。

### 第 4 步：只恢复被误改的课程文件

确认抢救副本存在后，再执行：

```bash
git checkout -- "01_mlp_lab/05_自主修改练习.ipynb"
```

这条命令会丢弃该课程文件中的本地修改，因此必须在复制并检查抢救副本之后执行。

这里使用 `git checkout -- 文件名`，是为了兼容课程服务器上较旧的 Git 版本。

### 第 5 步：检查并更新

```bash
git status --short --branch
git pull --ff-only origin main
```

最后确认抢救版仍然存在：

```bash
ls -lh "01_mlp_lab/我的作业_20260001_张三_MLP_抢救版.ipynb"
```

## 七、必须避免的危险操作

学生个人账号中，不要直接执行下面这些命令：

```bash
git reset --hard origin/main
git clean -fdx
rm -rf "$HOME/courses/Deeplearning2026"
```

原因：

- `git reset --hard` 会丢弃被 Git 跟踪文件中的本地修改；
- `git clean -fdx` 可能删除被 `.gitignore` 忽略的个人 Notebook；
- `rm -rf` 会删除整个项目目录，包括放在其中的个人文件。

课程公共目录的自动更新脚本可能由教师统一维护，但学生自己的项目目录不要照搬强制覆盖命令。

## 八、个人作业还要单独备份

`.gitignore` 只负责避免 Git 冲突，不等于备份。

建议每次课结束后至少完成一种备份：

- 通过 VS Code 下载个人 Notebook 到自己的电脑；
- 上传到课程作业平台；
- 复制到服务器项目目录之外的个人备份目录。

服务器备份示例：

```bash
mkdir -p "$HOME/deep_learning_backups"
cp -i \
  "01_mlp_lab/我的作业_20260001_张三_MLP.ipynb" \
  "$HOME/deep_learning_backups/"
```

解释：

- `mkdir -p` 创建备份目录；如果目录已经存在，也不会报错；
- 备份目录位于课程项目之外；
- 即使以后课程项目需要重新克隆，这份额外备份仍然存在。

## 九、常见问题

### 问题 1：个人 Notebook 会不会被 `git pull` 覆盖？

按照 `我的作业_学号_姓名_项目名.ipynb` 命名后，正常的 `git pull` 不会覆盖它。

但不要把个人文件命名成与课程原始文件完全相同的名字，也不要执行 `git clean -fdx`。

### 问题 2：我可以在项目中增加其他文件吗？

可以。名称不与教师将来发布的文件冲突时，普通未跟踪文件通常不会影响 `git pull`。

不过本课程最推荐使用统一的 `我的作业_*.ipynb` 命名，因为这类文件已经明确加入忽略规则。其他新文件应另外备份；如果 Git 提示它们将被覆盖，请停止操作并联系教师。

### 问题 3：为什么个人 Notebook 没出现在 `git status` 中？

这是预期结果。它被 `.gitignore` 忽略了，说明命名规则生效。

### 问题 4：旧个人 Notebook 在更新后还能运行吗？

通常可以，但旧 Notebook 可能会导入课程项目中已经更新的 Python 模块，因此重新运行时，结果可能与第一次课不同。

所以要同时保存：

- Notebook 当时的输出和图；
- 当时的课程 Git 版本号；
- 关键模型配置、随机种子和实验结论。

### 问题 5：`git pull` 提示本地修改会被覆盖，怎么办？

不要强行更新，也不要随意复制网上的解决命令。先执行：

```bash
git status --short
```

如果修改的是官方 Notebook，按照第六部分先抢救。如果出现其他文件，把完整提示发给教师判断。

### 问题 6：为什么不让初学者直接使用 `git stash` 或个人分支？

这些方法本身没有问题，但需要理解暂存区、分支、合并和冲突。当前课程重点是深度学习实验，所以先使用“个人副本”方案。以后学习完整 Git 工作流后，可以再使用个人仓库和分支管理版本。

## 十、上课速查表

### 第一次开始某个项目

```bash
cd "$HOME/courses/Deeplearning2026"
git status --short --branch
git pull --ff-only origin main
git rev-parse --short HEAD
cp -i "课程原始文件.ipynb" "同一目录/我的作业_学号_姓名_项目名.ipynb"
ls -lh "同一目录/我的作业_学号_姓名_项目名.ipynb"
```

### 下一次课更新课程代码

```bash
cd "$HOME/courses/Deeplearning2026"
git status --short --branch
git pull --ff-only origin main
git rev-parse --short HEAD
```

### 发现误改课程原始文件

```bash
git status --short
cp -i "被误改的课程文件.ipynb" "同一目录/我的作业_学号_姓名_项目名_抢救版.ipynb"
ls -lh "同一目录/我的作业_学号_姓名_项目名_抢救版.ipynb"
git checkout -- "被误改的课程文件.ipynb"
git pull --ff-only origin main
```

最后记住一句话：

> **先复制，后实验；先检查，后更新；先备份，后处理异常。**
